# Little Loops — Architecture & Contracts

Static PWA, plain ES modules, no framework, no build step, no dependencies.
Everything is served relative to `index.html`, so it runs from any GitHub Pages sub-path
(e.g. `https://user.github.io/little-loops/`). **Never use root-absolute URLs (`/foo`)** —
always relative paths (`data/x.json`, `./sw.js`) or `assetURL()` from `js/core/data.js`.

## Design rules (non-negotiable — ages 4–7; Loop Machine's `big`/`super` tiers stretch to 12 and may require reading)

1. **No reading required.** Every screen calls `ctx.instruct(text)` on arrival, which speaks
   the instruction and registers it with the always-visible replay (speaker) button. Any
   prompt the child must understand is spoken. Text on screen is only a bonus for grown-ups.
2. **Tap and drag only. No typing.** Every interactive element is **≥ 64×64 CSS px**
   (`--tap` in `css/base.css`). This includes palette swatches, cards, slots, close buttons.
3. **Original, bright, simple SVG art.** No copyrighted characters, no emoji as art (they
   render differently per platform), no external images or fonts.
4. **No failure screens.** Mistakes get a gentle `sound.play('tryAgain')` + kind spoken
   encouragement. After **2 misses** on the same task, show a hint (Loop Machine: or as soon
   as only two answers remain). Never show "wrong",
   "fail", red X, game-over, or lose progress.
5. **Celebrate success** with `ctx.celebrate()` (animation + sound) and a spoken
   `ctx.praise()`.
6. **Parent gate** (`ctx.parentGate()`, press & hold 3 s) before printing or settings.
7. **Privacy.** No network calls other than same-origin static files. No analytics, no
   accounts. Progress in `localStorage` only (via `ctx.store`). CSP in `index.html`
   enforces `default-src 'self'`; inline `<script>` is blocked, so never use inline
   handlers or `javascript:` URLs; style *attributes* in markup are allowed.
8. Works in **portrait and landscape** on phones (≥ 360 px wide) and tablets, with no page
   scroll on game screens (level select / settings may scroll inside their own container).
9. Respect `prefers-reduced-motion` (base.css shortens animations globally).

## Module contract

```js
// js/modules/<id>/<id>.js
export default {
  id: '<id>',
  // Called on every route into the module (#/<id>/...). `root` is an empty <div class="screen-root mod-<id>">
  // that fills the area under the top bar. May be async. May return a cleanup function.
  mount(root, ctx) { ... },
  unmount() { ... },               // optional; called before leaving
  settings: [                      // optional grown-up settings (rendered by core/settings.js)
    { key: 'unlockAll', label: 'Unlock all levels', type: 'toggle', default: false, hint: '...' },
  ],
};
```

`type: 'toggle'` is the only setting type: `core/settings.js` shows every module setting as an
on/off switch that stores a boolean in the module's store (`<id>.<key>`; `default` falls back to
`false`) and ignores `type`. Each ready module gets its own section (titled with its registry
`title`, in registry order) that appears once the module's code has loaded. Module settings
survive "Reset progress".

The app unmounts and remounts the module on **every** hash change (including `#/robot/3` →
`#/robot/4`), so `mount` must fully (re)build the screen from `ctx.params` and storage.
Module-level mutable state must be reset in `mount`. JSON is cached by `loadJSON`, so
remounting is cheap.

### `ctx` (built in `js/app.js` → `makeContext`)

| member | purpose |
|---|---|
| `ctx.app` | `APP` from `js/config.js` (name, version, storage key) |
| `ctx.id` | this module's id (`'robot'`) |
| `ctx.entry` | this module's entry from `data/app.json` (`{ id, title, status, entry, css, tile }`) |
| `ctx.params` | route segments after the module id: `#/robot/3` → `['3']` |
| `ctx.instruct(text, {speak=true})` | set + speak the screen instruction (replay button repeats it; caption shows it) |
| `ctx.say(text, opts)` | speak without changing the replay text (feedback, praise). Returns Promise<bool> |
| `ctx.chrome.setBack({icon:'home'\|'back', to:'#/x' \| fn, label})` / `setBack(null)` | top-left button. Default: home → `#/` |
| `ctx.chrome.setActions([buttons])` | extra 64px round buttons in the top bar (left side, after back) |
| `ctx.chrome.instruction` | the current instruction text (what the replay button speaks) |
| `ctx.sound.play(name)` | `tap select pick drop remove step bump tryAgain success fanfare fill locked unlock whoosh` |
| `ctx.celebrate({big})` | confetti + success/fanfare sound; resolves when done (~1.5 s / ~2.4 s) |
| `ctx.praise()` | random praise phrase ("Great job!") — speak it with `ctx.say` |
| `ctx.parentGate()` | Promise<boolean> — 3 s press-and-hold overlay |
| `ctx.navigate('#/robot/4', {replace})` | change route |
| `ctx.loadJSON('data/robot/levels.json')` | cached fetch relative to index.html |
| `ctx.asset('art/robot.svg')` | absolute URL for an app-relative path |
| `ctx.store.get(key, fallback)` / `.set(key, value)` | localStorage scoped to the module (`<id>.<key>`) |
| `ctx.onCleanup(fn)` | run fn on unmount (timers, listeners, animations) |
| `ctx.isActive()` | false once unmounted — check after every `await` |

Modules may import core helpers directly, e.g.
`import { h, icon, flash, wait } from '../../core/dom.js'` and
`import { draggable, cancelDrag } from '../../core/drag.js'`.

### Screen changes (`core/tapguard.js`)

Kids double-tap, so the second tap must never act on the next screen. On every route change
`js/app.js` holds taps on `#app` until the new screen is painted plus 400 ms (a rapid burst
keeps being ignored while it lasts; overlays such as the parent gate are never blocked). A
module that swaps a whole screen **without** a route change (e.g. the coloring wizard's steps)
calls `releaseTaps()` from `../../core/tapguard.js` right after the swap. While a slow first
load is in progress a "Getting ready!" placeholder appears after 0.4 s (spoken after 1 s).
`ctx.instruct` is a no-op once the screen is gone; a mount that throws shows the Oops screen and
its cleanups run at once. Tests wait for `!document.body.dataset.tapGuard` before tapping.

### `core/drag.js` notes

`draggable(el, { onTap, onStart, onMove({x,y,over}), onDrop({x,y,over}), onCancel, ghost })`
returns an `off()` function. It uses pointer events + pointer capture, sets
`touch-action: none` on the element, creates a floating ghost, and reports the element
under the finger (`over`) via `document.elementFromPoint`. Use `onTap` for taps on
draggable elements — **do not** also add `click` listeners to them. Don't re-render
(remove) the element being dragged until `onDrop`/`onCancel` fires — removing it cancels
the drag. Only one drag at a time app-wide.

### Speech notes

Keep spoken sentences short (≤ ~15 words, Chrome cuts long utterances), in US English
(color, gray, favorite, mom), with no symbols, emoji or markup. `ctx.instruct`
interrupts whatever is speaking. Feedback lines via `ctx.say` also interrupt by default;
pass `{ interrupt: false }` to queue.

## Content is data

All content lives in JSON under `data/`, validated by `tools/validate-*.mjs` (all run by
`tools/validate.mjs`, which also checks every spoken line: no markup, no emoji, no scolding,
US English) and described by JSON Schemas in `schemas/`. Rendering code never hard-codes levels or art parts, so a
later AI feature can generate new files in the same format, validate them with the same
tools, and drop them in. Renderers sanitize content (numbers coerced, path data checked
against a whitelist) so generated content can't inject markup.

## Module spec: Robot Puzzles (`js/modules/robot/`)

Teaches sequencing (levels 1–9) and loops (levels 10–15).

**Rules** are in `js/modules/robot/logic.js` (pure). The game must use `simulate()` from
there — never re-implement movement rules. Coordinates `[col,row]`, `[0,0]` = top-left.
Success the instant the robot enters the star cell. Blocked moves (edge/obstacle) stop the
run on that step.

**Level JSON** (`data/robot/levels.json`; every field is described in `docs/CONTENT-FORMAT.md`
§5 and `schemas/robot-levels.schema.json`). An example loop level from a generated pack:
```json
{
  "schema": "robot-levels/1",
  "grid": { "cols": 4, "rows": 4 },
  "levels": [
    {
      "id": "g01",
      "start": [0, 3],
      "goal": [3, 2],
      "obstacles": [ { "at": [1, 2], "kind": "rock" } ],
      "cards": ["up", "right", "repeat3"],
      "maxCards": 2,
      "repeatCapacity": 1,
      "say": "The repeat card does the arrow inside it again and again!",
      "hint": "Put the right arrow inside the repeat card.",
      "solution": [ { "repeat": 3, "do": ["right"] }, "up" ]
    }
  ]
}
```
- `cards`: palette — any of `up down left right repeat2 repeat3` (unlimited copies of each).
- `maxCards`: number of top-level slots in the command strip (a repeat block uses one slot).
- `repeatCapacity`: arrow slots inside each repeat block (1–3, default 2).
- `obstacles[].kind`: `rock` | `bush` | `puddle` (all block movement; purely visual difference).
- `say`: spoken intro (short). Optional `hint`: spoken when the hint appears.
- `solution`: a reference program (validator proves it works and fits the limits).

The main file `data/robot/levels.json` is also checked as the curriculum: exactly 15 levels
`r01`..`r15`; levels 1–9 have no obstacles and no repeat cards; levels 10–15 have at least one
obstacle and a repeat card (and must need it). Generated packs use their own ids (`g01`…) and
are validated with `node tools/validate-levels.mjs pack.json --no-curriculum`.

**Screens**
1. **Level select** `#/robot` — 15 big numbered buttons (≥ 64 px, number + star when done).
   Level N is playable when level N−1 is done (level 1 always), when level N itself is
   already solved, or when the grown-up setting "Unlock all puzzle levels" is on
   (`isUnlocked()` in levels.js); locked ones show a lock and speak "Finish the puzzle
   before this one first!" when tapped. The next unsolved level pulses with the robot
   sitting on it. Instruction: "Pick a puzzle!" Back → home.
2. **Puzzle** `#/robot/<n>` (1-based). Anything that is not a level number, and a locked
   puzzle opened directly (a link, Back/history after a progress reset, a bookmark),
   redirects to `#/robot` (replacing the history entry).
   - **Top bar**: Back (→ `#/robot`, "All puzzles"), **Clear** (trash, "Clear the strip"),
     a level-number badge ("Puzzle N"), then the shared replay button. Clear lives in the
     top bar so the strip can use the full width. It empties the strip with a poof
     (`remove` sound) and sends the robot back to the start. It is dimmed (`is-off`) while
     the robot runs and while the strip is empty; tapped with an empty strip it only wobbles.
   - **Board**: 4×4 grid, robot (`art/robot.svg`), a star goal, obstacles. Large, square,
     as big as the layout allows.
   - **Command strip**: `maxCards` empty slots (dashed). Cards dropped in fill slots in
     order (no gaps; inserting between cards shifts the rest). A repeat block shows its
     badge (×2 / ×3) and `repeatCapacity` inner slots for arrows.
   - **Palette**: one card per entry in `cards` (it never runs out). Arrow cards show a big
     arrow, each direction a different color. Repeat cards show a loop icon + "×2"/"×3"
     (digits are fine; also spoken when tapped/dropped: "Repeat two times!").
   - **Interactions**: drag palette card → strip (drop on a slot/card inserts there; drop
     anywhere else on the strip appends). Drag an arrow onto a repeat block's inner slot
     to fill it. **Tap** a palette card → append it (if the last strip item is a repeat
     with an empty inner slot, a tapped arrow goes inside it). Tap a strip card → removes
     it (poof animation + `remove` sound); a fast double tap removes only that one card
     (the card that slides into its place ignores a second tap within ~350 ms). Drag a
     strip card out of the strip → remove it; drag within the strip → reorder. Every
     placed card speaks its name briefly ("Up!"). When the strip is full, extra cards
     bounce back with a gentle sound + "The strip is full!".
   - **Play** (big green ▶):
     - Strip empty → the strip shakes, the first palette card wobbles, and "Put some
       arrows in the strip first!" (not a miss).
     - Only repeat cards with nothing inside them (no move to make; `simulate()` outcome
       `empty`) → the inner slots shake and "Put an arrow inside the repeat card!" (not a
       miss). An empty repeat card next to arrows simply does nothing.
     - Otherwise the robot whooshes back to the start if it is elsewhere, editing locks,
       and `simulate()` runs, animated step by step (~520 ms per move): highlight the
       active card (and inner card + a 1/2/3 iteration counter on repeat blocks), `step`
       sound per move.
     - While the robot runs, Play stays a dimmed Play button (`is-running`,
       `aria-disabled`): extra taps are ignored and there is **no Stop**, so a double tap
       or an impatient second tap never stops the robot. Back still leaves.
   - **Outcomes**:
     - `goal` → robot dance, the star is collected, the level is marked done (`ctx.store`
       `done.<levelId>` = true). About 0.75 s later the win card appears with
       `ctx.celebrate()`; the robot says `ctx.praise()`, then (queued) "Tap the green
       arrow for the next puzzle!", and the caption shows both. The win card holds
       **Levels** (→ `#/robot`), **Again** (empties the strip, robot back to the start,
       hint and misses reset, intro spoken again) and a big green **Next** (→ next
       level). It sits over the controls, beside or under the board, so the board with
       the robot on the star stays visible; only when there is no room there does it
       overlap the board, on the side away from the robot.
     - `goal` on the **last level** → `celebrate({big:true})`, no Next button, and the line
       is "You solved every puzzle!" only when every level is done, otherwise "You solved
       the last puzzle!".
     - `edge` / `obstacle` → robot bumps toward the blocked direction and **stays where it
       stopped**; the card that caused it gets an orange "look here" glow; `tryAgain`
       sound; speak "Oops, bump! Can you fix the arrows?" Counts as a miss.
     - `short` → robot stays where it stopped; the line says what can still fix it:
       "So close! The robot needs more arrows to reach the star." only when filling the
       strip's empty places (free slots, empty inner slots) can still reach the star
       (`canFinishByFilling()` in program.js); otherwise "So close! Try changing an arrow."
       when the robot stopped one step from the star, else "Hmm, the robot didn't reach the
       star yet. Try different arrows!". Counts as a miss.
   - **Debugging**: after a miss the robot stays on the board where it stopped and the
     strip stays as it was so the child can fix it. Editing is re-enabled immediately.
     Next Play starts again from the start cell.
   - **Hint after 2 misses** (per level visit): draw the reference solution's path as
     glowing dots/footprints on the board (`solutionPath()` from logic.js); the level
     `hint` (or "Here's a hint! Follow the sparkly dots.") is queued behind the kind words.
     Stays until solved (or Again).
   - **Concept intros** are the levels' own `say` lines, spoken on every visit (there is no
     separate first-time line): r03 / r05 / r06 introduce the up / left / down arrows, r10
     the repeat card and obstacles ("Put the arrow inside the repeat card. It goes three
     times! Rocks block the way."), r11 both repeat cards, r13 two-arrow loops. Repeat
     palette cards also glow (`is-new`) until the child first places one (`ctx.store`
     `seen.repeat`, i.e. `robot.seen.repeat`).
   - **Idle nudges**: after 7 s with nothing happening and an empty strip, a ghost card
     with a finger glides from the first palette card into the strip (at most 3 per visit;
     with reduced motion the first palette card wobbles instead). With cards in the strip,
     Play pulses (`rb-nudge`). Nudges come back every 10 s; touching a card, an edit, Play or
     Clear restarts the wait; they stop once the level is solved.
   - Grown-up setting: `{ key: 'unlockAll', label: 'Unlock all puzzle levels', type: 'toggle' }`.

**Layout**: the board is as big as possible. Landscape → board left, controls on its right;
portrait → board on top, controls below. The controls are the strip on top and the palette
below it; Play goes at the end of the palette row, at the end of the strip row
(`is-play-strip`) or on its own row (`is-play-below`), whichever leaves the biggest board.
Cards are 64–96 px (`CARD_SIZES`; bigger only when the board does not shrink). The strip
reserves the height of the level's reference solution from the start, so nothing jumps while
the child builds it. Only extreme programs (tiny phone + many repeat blocks) make the strip,
and then the controls, scroll inside themselves; the page never scrolls (360×640 and up).

## Module spec: Coloring (`js/modules/coloring/`)

**Art JSON** (`data/coloring/animals.json`, `accessories.json`, `backgrounds.json`) —
rendered only through `js/modules/coloring/scene.js`. See that file's header and
`docs/CONTENT-FORMAT.md`.
```json
{ "schema": "coloring-parts/1", "kind": "animal",
  "placement": { "x": 120, "y": 210, "scale": 1.2 },
  "items": [ { "id": "cat", "name": "Cat", "say": "A cat!", "anchors": { "head": {"x":150,"y":52,"scale":1}, "eyes": {...}, "neck": {...}, "hand": {...} },
               "shapes": [ { "type": "ellipse", "kind": "region", "cx": 150, "cy": 200, "rx": 80, "ry": 70 } ] } ] }
```
Accessories: `{ "id": "party-hat", "name": "Party hat", "say": "A party hat!", "anchor": "head", "shapes": [...] }`.
Backgrounds: `{ "id": "meadow", "name": "Meadow", "say": "A sunny meadow!", "shapes": [...] }`.
`placement` puts the 300×300 animal box into the 600×600 scene. The shipped animals.json uses
`{ "x": 120, "y": 210, "scale": 1.2 }`, so the animal covers scene x 120..480, y 210..570 (the
"stage box"); without `placement` the renderer uses `{ "x": 150, "y": 270, "scale": 1 }`.

**Flow**
1. `#/coloring` — **Make a picture** wizard, 3 steps, each a grid of big picture tiles (one
   per part; the files are designed for 6 each):
   1. "Pick an animal!" (animal thumbnails)
   2. "Pick something to wear!" (tiles show the chosen animal wearing each accessory)
   3. "Pick a place!" (tiles show the full scene on each background)
   Tapping a tile speaks its `say`, highlights it and advances after ~600 ms. Step dots
   at the top (beside the grid on short landscape screens); back button goes to the
   previous step (step 1 → home). Finishing step 3 starts that picture, blank, on the
   paint screen. Top bar: first the brush **Keep painting my picture** button (only when a
   picture is saved; it sits exactly where the paint screen's New picture button was, so a
   double tap on New picture lands on it harmlessly), then the **Surprise me** dice (a
   random combo, different from the saved one, started blank; the paint screen says
   "Surprise!" first).
2. `#/coloring/paint` — **Paint**: the composed scene (`renderScene` mode `color`) as
   large as possible; 12-color palette (big round swatches ≥ 64 px, selected one
   enlarged with a ring; tapping speaks the color name: "Red!"; the last color is
   remembered); tap a region → fills with the selected color (`fill` sound, quick pop
   animation, a splash).
   - **Tap help** (`tapassist.js` is the source of truth for the numbers): regions smaller
     than ~30 px on screen get an invisible margin (at most 11 px); a tap on an outline or
     in a gap takes the nearest region within 8 px; a wobble of up to max(20 px, 5% of the
     picture) still counts as a tap; a scribble that starts and ends in the same shape
     paints it.
   - **Top bar**: **New picture** (saves, back to the wizard) and **Print** ("Print
     (grown-ups)", behind `ctx.parentGate()`).
   - **Undo** sits with the palette: an extra column beside the swatches or its own row
     under them (`paintLayout()` picks). It reverts the last fill (up to 300 steps); with
     nothing to undo it is a harmless no-op that wobbles with a gentle sound.
   - **Picture done**: when 75% of the regions are colored (once per picture):
     `ctx.celebrate()` + "<praise> What a beautiful picture!".
   - Palette: red, orange, yellow, light green, green, light blue, blue, purple, pink, brown,
     peach (skin), white (works as an eraser).
   - **Saving** (`parts.js`): the current picture (part ids + fills + done) is saved in
     `ctx.store` (`coloring.picture`) shortly after every fill and when the screen is left
     or the app is hidden, and is restored whenever `#/coloring/paint` opens (e.g. a reload
     on that screen). Finishing the wizard or tapping Surprise always starts a fresh blank
     picture, even for the same combo (`choosePicture()`); if the picture being left has any
     color, it is first kept as the previous picture (`coloring.previous`, one slot: a newer
     colored picture replaces it, an uncolored one never does). **Keep painting**
     (`resumePicture()`) reopens the current picture if it has color, otherwise it brings
     the previous colored picture back (the blank pick is dropped), so tapping the dice
     again and again never loses the last painting. If `#/coloring/paint` is opened with
     nothing saved, the first animal, accessory and background are used.
3. **Print** — after the gate: render the scene with `mode: 'print'` (all regions white,
   black outlines) into `#print-root` (sized to fill one page, portrait, no UI) and call
   `window.print()` synchronously in the gate's finger-lift event (iPad/iPhone only open the
   print sheet from a fresh tap). If `navigator.userActivation.isActive` is false by then, a
   "Ready! Tap to print." card with one big printer button appears instead (the instruction
   becomes "Tap the printer to print!") and printing happens from that tap; its close
   button, Escape or a tap outside the card cancels. `#print-root` is cleared on
   `afterprint` (one arriving within 1 s is ignored: some mobile browsers fire it before the
   sheet has captured the page), after a 60 s fallback, and on unmount. The browser's own
   Print (Ctrl+P / menu) on the paint screen prints the outline too (`beforeprint`).
   `css/base.css` hides the app and shows only `#print-root` in print media.

**Layout**: landscape → picture left, swatch grid on the right: usually 3 columns; short wide
phones get 4 columns, or 6 columns in two rows. Undo goes beside or below the grid. Portrait →
picture on top, 4–6 swatches per row, Undo beside or under them. The exact grid comes from
`paintLayout()` in `layout.js`. No page scroll at 360×640 and up.

## Module spec: Loop Machine (`js/modules/machine/`)

A puzzle machine for **ages 4–12**: the machine runs a "loop" (a repeating pattern, a number
rule, or a word puzzle) along a conveyor belt with one mystery **?** box; the child picks the
right answer. Three difficulty tiers chosen by robot size (no reading needed to choose):

| tier id | shown as | ages | content |
|---|---|---|---|
| `little` | small robot, 1 star | 4–6 | **no reading**: picture loops with one changing attribute (AB, AAB, ABB, ABC); counting 1–9 pictures, including only the target among other pictures and by shape + color ("how many red hearts?"); +1 number lines up to 20 (what comes next, just before, the missing one); more / fewer / most / fewest among 2–3 picture groups (optionally counting only a target) |
| `big` | medium robot, 2 stars | 7–9 | skip counting by 2, 3, 4, 5, 7, 10, 25 and back by 1, 2, 10; doubling; missing middle numbers; rhymes, opposites, compound words, missing letters, word families, plurals (incl. irregular: mice, sheep, teeth), simple analogies, category groups (animals, foods, things with wheels…); 4–6 word sentence ordering; AABB / ABCD / growing picture loops |
| `super` | big robot, 3 stars | 10–12 | genuinely challenging: doubling / halving / ×3, bigger steps (+15, −7), squares, cubes, triangular numbers, primes, Fibonacci-like (add the two before), alternating rules (+3 −1, ×2 +1), counting back into negatives; synonyms, antonyms, analogies, homophones in context (their / there / they're), prefixes / suffixes; verb / adjective / noun / adverb / category / synonym groups; 6–8 word sentences with a comma; two-attribute picture loops |

The bank (`data/machine/rounds.json`) has 146 rounds: little 45, big 52, super 49. The
generator-facing tier descriptions in `schemas/machine-rounds.schema.json` must stay in sync with
this table.

Questions are always spoken. In `big`/`super`, reading the answer words IS the challenge, so
answers are not read aloud unless the grown-up setting **"Read word answers aloud"**
(`readAloud`) is on or the hint is showing.

**Picture tokens** come from `js/modules/machine/tokens.js` (pure): numbers, words/letters,
symbols `→ + = ?`, and picture ids (`circle-red` … `diamond-orange`, `apple fish flower balloon
cupcake moon cloud ladybug`). Render with `tokenSVG()` / speak with `tokenName()`.

**Content** (`data/machine/rounds.json`, schema `schemas/machine-rounds.schema.json`, validator
`tools/validate-machine.mjs`):
```json
{
  "schema": "machine-rounds/1",
  "sessionLength": 10,
  "tiers": [ { "id": "little", "name": "Little", "ages": "4-6", "stars": 1, "say": "Little machine! Easy puzzles." } ],
  "rounds": [
    { "id": "l-pat-01", "tier": "little", "level": 1, "type": "pattern",
```

- `type`: `pattern` (picture tokens; `show` has one `?`), `count` (`show` = pictures, `target`
  = which picture to count, answer = that count), `sequence` (numbers; optional machine-checked
  `rule`), `word` (words/letters/symbols), `set` (each choice is an array of tokens), `order`
  (`words` in the correct order; the game shuffles them).
- `level` 1–3 = difficulty within the tier. 2–4 `choices` (unique, include `answer`) except `order`.
- `say` = spoken question (≤ 15 words). `hint` = spoken hint. `explain` = spoken after a
  correct answer (teaches the rule). `ruleLabel` = short visual hint label (e.g. "+2").

**Screens**
1. `#/machine` — tier picker: three big buttons with robots of increasing size and 1/2/3
   stars; each shows the best score earned. Instruction: "Pick your machine! One star is easy.
   Three stars is tricky!" Age range in small text for grown-ups.
2. `#/machine/<tier>` — a session of `sessionLength` rounds chosen from that tier, ramping from
   level 1 to 3, mixed types (never the same type 3× in a row), avoiding recently played ids
   (keep the last ~30 per tier in `ctx.store`). A progress meter of `sessionLength` slots.
   - The machine: a cheerful SVG machine with a conveyor belt; `show` tokens slide in one by one
     (`step` sound), the `?` box pulses. Answer buttons (≥ 72 px tall, big text/pictures) below.
   - **Tap** an answer (or drag it onto the `?` box) → correct: it flies into the box, the
     machine lights up and "loops" (the sequence wiggles in rhythm), `success` sound,
     `ctx.say(explain || praise())`, a **gold** star (first try) or **silver** star drops into
     the meter, next round after a beat. Wrong: the button wobbles and grays out (stays visible,
     disabled), `tryAgain` sound, kind spoken nudge. **Hint** after 2 misses, or as soon as
     only two answers are left (after the first miss with 3 choices): speak `hint` (or a
     default line for the round type), show `ruleLabel` / bracket one repeat of the loop /
     arrows between numbers / highlight the pictures to count, and read the two answers still
     in play aloud. The hint never removes an answer, so it always leaves a real choice; a
     2-choice round has no hint (one miss leaves only the answer) and just gets a nudge. A
     round always ends with the child finding the answer.
   - `order` rounds: word cards in a shuffled tray; tap a card → it goes to the next empty
     sentence slot (tap a placed word to send it back; drag also works). When all slots are
     full: correct → success; otherwise words already in the right spot lock in place with a
     green glow, the rest bounce back to the tray (miss). Hint after 2 misses: the next correct
     word hops into its place by itself (and again after every later miss).
   - End of session: big celebration, the machine "prints" a prize (stars earned, e.g. 8 gold
     2 silver), buttons **Play again**, **Machines** (tier picker). Save best gold count per tier.
3. Grown-up settings: `readAloud` toggle ("Read word answers aloud"), default off.

**Layout**: landscape → machine/belt top-left, answers right or below; portrait → belt top
(tokens shrink/wrap to fit up to 9 items), answers in a 2×2 grid below. No page scroll at
360×640 and up. Long `set` and `order` content must still fit (smaller font, wrapping chips).

   the module-settings loop in `js/core/settings.js`.

## Before every deploy

`sw.js`'s cache version is a hash of every file the app serves (`index.html`, the manifest and
`css/ js/ data/ art/ icons/`), so it goes stale whenever any of them changes. Always run
`node tools/precache.mjs` (then `npm run precache:check`, `npm run validate`, `npm test`) before
publishing — a stale `sw.js` means returning visitors never receive the update. The same is true
on your own computer: the service worker also runs on `localhost` and serves its cached copy, so
run the precache step to see your edits there too (README, "Run it on your computer").
If any of these reports ERROR, STALE or FAILED, do not publish: fix it first, or copy the
failing lines and ask a developer.
